# 提了么 · 小程序真机验收手册

版本 0.1.0 · 数据全部保存在本机（`wx` storage，键前缀 `tgm:`）· 本版本无云端、无登录
适用对象：拿到手机、能在微信里操作的人或代理（agent）。逐条执行，逐条判定。

---

## 0 前置

### 0.1 进入方式

1. 打开 WorkBuddy 对话里的应用卡「提了么」。
2. 预览面板右上角 →「分享 / Share」→ 试用小程序 → 生成小程序码。
3. 手机微信扫码打开。首次会提示「未发布的小程序」，正常。

当前状态为**未发布**。每次代码变更后需重新走一遍上面的步骤更新体验版。

### 0.2 设备矩阵

| 项 | 要求 |
|---|---|
| iOS | 1 台，建议带静音拨片（验提示音） |
| Android | 1 台，建议 1 台低端机（验动画与滚动） |
| 微信版本 | 8.0.30 以上 |
| 网络 | 不要求。本版本不联网，断网应完全可用 |
| 时长 | 约 35 分钟／台 |

### 0.3 复位

用例之间需要干净数据时，执行：

**设置 → 数据 → 清空本机记录 → 清空**

它会同时重置训练记录、连续天数、设置（目标回 3、主题回跟随系统、三个开关回开）、默认方案回「入门」。
若要保留设置，只验证记录，跳过复位即可。

### 0.4 预览环境的已知限制（H5 预览 ≠ 真机）

WorkBuddy 内置 H5 手机预览里，以下接口不支持，会在控制台打印「暂不支持」：

| 接口 | 预览表现 | 影响判定吗 |
|---|---|---|
| `wx.vibrateShort` | 抛错 | **不影响**。反馈能力不可用时训练必须照常推进（C14 专测） |
| `wx.hideTabBar` / `showTabBar` | 不生效，tabBar 常驻 | **不影响**。预览里 tabBar 盖不住属宿主限制，B6 只在真机判定 |
| `wx.createInnerAudioContext` | 可能不可用 | 不影响。静音缺失不等于训练失败 |

因此**在预览里跑出来的 B6、C5 声音、C6 震动相关 FAIL，一律不下结论**，标记 `ENV` 转真机。

### 0.5 判定与回报

- 每条给 `PASS` / `FAIL`，FAIL 必须附：编号、机型、系统版本、微信版本、实际现象、截图或录屏。
- **阻断级**（任意一条命中即整体不通过）：白屏、闪退、覆盖层关不掉、同一组记录入库两次、清空后数据还在。
- 记录模板：

```
机型 / 系统 / 微信版本：
A1 PASS  A2 PASS  A3 FAIL（截图 a3.png，本周条第 7 格没有描边）
...
```

## C 训练与播放层

进入方式：今日页 CTA，或「训练」tab 点任意方案卡。

| 编号 | 操作 | 预期 |
|---|---|---|
| C1 | 点「入门」方案卡 | 进入准备阶段：小字「准备」、大数字 `3`、提示「找个舒服的姿势，跟着节拍」、底部按钮「取消」 |
| C2 | 观察准备倒计时 | `3 → 2 → 1`，每个数字约 0.66 秒（合计约 2 秒），属设计值，不是卡顿 |
| C3 | 准备阶段点「取消」 | 立即退回；记录页当天仍为 0 组（**不产生记录**） |
| C4 | **第一段收紧（重点回归）** | 从准备切到「收 · 紧」的**第一下就要看到圆在收**：由 1.05 倍收到 0.82 倍，跟着 3 秒走完。不得出现「静止的红球」——这是已修的问题，旧实现第一次收紧无动画 |
| C4b | 进入呼吸阶段后的循环 | 文字「收 · 紧」→「放 · 松」交替；圆形随阶段放大/收缩，时长与方案参数一致（入门各 3 秒）；两段之间没有跳变 |
| C5 | 看底部信息 | 形如「1 / 1 组 · 0 / 10 次」，随完成次数递增；中央数字从 3 递减到 1 |
| C6 | 呼吸阶段点「暂停」 | 按钮变「继续」；圆形冻结在原尺寸；计数停住 |
| C7 | 点「继续」 | 恢复计时与动画，不跳秒、不错位 |
| C8 | 点「结束」 | **不弹二次确认**，立即退回；已完成的次数入库，记录页该次标为「部分」 |
| C9 | 重新开始，做完一整组 | 结束页显示「完成」+ 一行回执「完成了 10 次收紧，做得好。」；按钮只有「分享这次」「好的」 |
| C10 | 停在结束页不动 | 约 1.8 秒后自动关闭并回到原页面 |
| C11 | 快速连点两次「好的」 | 只入库一次，今日数字只 +1（不得 +2） |
| C12 | 看今日页 | 大数字变 `1`；**仍不显示连续天数卡片**（1 组未达「每天 3 组」的目标，连续从达标当天才开始计，见 D 组） |
| C13 | 训练中点右上角「×」 | 与「结束」等效：有次数则记「部分」，无次数则不记 |
| C14 | 关掉「声音」「触感反馈」后，从**记录页 → 今天 →「去训练」**进入 | 准备倒计时走完必须进入呼吸阶段；不得停在 `1`（这是曾出现的回归路径，务必单独跑一遍） |
| C15 | 训练全程观察底部 | 准备、呼吸、完成三个阶段都看不到 tabBar；关闭后 tabBar 恢复且四项可点 |

> 覆盖层是全屏：训练中顶部状态栏、底部 home 条之外的区域应无 tabBar 残留。

## D 达标、连续与里程碑

| 编号 | 操作 | 预期 |
|---|---|---|
| D1 | 设置 → 每日目标点「−」到 1 | 显示 1；此时「−」变灰不可点 |
| D2 | 回今日页看 CTA | 若已有 1 组记录，数字变强调色、标题变淡、CTA 变「今天，提了。再来一组」 |

| D4 | 关掉卡片，再完成一组 | **不再**弹里程碑（当天只弹一次） |
| D5 | 次日再做（可改系统时间到明天，杀进程重进） | 昨日达标 + 今天未达标时，连续显示 1；今天达标后变 2 |
| D6 | 把目标改回 3 | 今日页立即按 3 判定；历史天不追溯改变 |

## I 已知风险专项（重点看，出问题不影响其他条判定）

| 编号 | 关注点 | 说明 |
|---|---|---|
| I1 | 呼吸圆动画 | 低端机是否出现跳变、卡顿、圆变成方；过渡时长是否与「收紧 3 秒」体感一致 |
| I2 | iOS 静音键 | 提示音在静音拨片打开时是否仍响（设计上走系统提示音通道，应仍响）；音量是否过小或过尖 |
| I3 | 相册授权被拒 | 拒绝后再点保存，应弹出引导去「设置 → 微信 → 照片」的提示，而不是静默失败 |
| I4 | 底部安全区 | 全面屏机型上，覆盖层底部「暂停 / 结束」与 tabBar 不被 home 条压住 |
| I5 | 小屏适配 | iPhone SE 类机型：方案卡四个参数是否换行整齐、长文案是否截断 |
| I6 | 深色对比度 | 深色下正文与次要文字（灰字）是否仍可读，热力空格是否与底色混淆 |
| I7 | 震动 | Android 上 `type` 参数是否生效（medium / light 有区别）；部分机型可能忽略，记录机型即可 |

## J 汇总

全部 PASS 后，按 0.4 的模板回报。任何 FAIL 请附截图，并注明是**阻断级**还是**一般级**。

已知与 App 端的两处平台差异，**不算缺陷**：

1. 卡片上没有二维码 —— 小程序本身可直接转发，不重复放码。
2. 「GitHub」行不能直接打开浏览器 —— 微信不允许，改为复制链接。
3. 系统「减少动态效果」开关读不到 —— 呼吸动画恒开。
