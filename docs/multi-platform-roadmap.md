# 小程序实施方案

更新日期：2026-11-15。代码基线：`main`，`2cfb58501213b30f3308c76cd190644b7bc3f476`。

本文是小程序这一端的实施依据：形态、技术选型、数据结构、安全要求和验收顺序都在本文内说明，不需要外部前提即可执行。

## 1. 方案概要

| 项 | 内容 |
| --- | --- |
| 形态 | 原生微信小程序，WXML / WXSS / JS，工程由脚手架生成 |
| 定位 | 国内用户的训练入口，支持不登录的本地训练 |
| 数据 | 本地存储为主，用户主动开启后同步到云端 |
| 后端 | WorkBuddy 托管云服务：数据库、认证、文件、LLM 共用一个环境 |
| 登录 | 邮箱验证码、手机短信验证码、邮箱或手机 + 密码、微信登录、WorkBuddy 账号 |
| 发布 | 应用卡预览，在预览面板「分享」中绑定小程序并上架 |
| 不影响 | Web 与 App 保持现状，各自的本地数据与发布方式不变 |

首版范围：一次完整训练、历史与热力图、计划与设置、可选云同步、自愿参与的打卡榜与邀请制挑战。数据按用户隔离，榜单只公开昵称和分数。

## 2. 现有代码可复用什么

| 位置 | 当前实现 | 在小程序中的用法 |
| --- | --- | --- |
| `apps/web` | React + Vite，数据入口为 `src/data.ts` | 独立运行，不参与小程序构建 |
| `apps/mobile` | Expo + React Native | 独立运行，不参与小程序构建 |
| `packages/core` | 训练节拍器、打卡、连续天数和统计逻辑 | 编译为 CommonJS 后放入 `lib/core.js` 供页面 `require` |
| `packages/data` | `Store`、同步存储接口和数据模型 | 复用数据结构定义，存储接口另写异步适配 |
| `packages/store` | Zustand 状态层 | 页面状态由页面自身管理，状态层不进入小程序 |
| `packages/design-tokens` | 颜色和其他设计参数 | 数值沿用，样式改写为 WXSS |
| `packages/share-card` | 分享卡片的数据组装和文案 | 复用文案组装，绘制使用小程序 Canvas |

Web 使用 `localStorage`，App 在启动时从 `AsyncStorage` 预载。现有键为 `tgm:settings`、`tgm:plans`、`tgm:streak`、`tgm:log:YYYY-MM-DD`。

小程序运行环境没有 `document`、`window`、`localStorage` 和浏览器 `fetch`，依赖这些的组件要在小程序内重写。共享逻辑以编译产物形式进入工程：原生小程序没有打包器，`packages/core` 的 TypeScript 源码不能在页面里直接引用。

## 3. 原生工程约束

工程按原生结构组织，以下为硬性要求：

- `project.config.json` 的 `miniprogramRoot` 指向含 `app.json` 的源码根。
- `app.json.pages` 非空，每个页面有对应的 `.wxml`、`.js`、`.wxss`。
- `app.json` 顶层包含 `"lazyCodeLoading": "requiredComponents"`。
- JSON 严格合法，不含注释与尾逗号。
- 使用 `<view>`、`<text>`、`<image>` 等小程序组件。
- WXML 表达式不使用可选链、空值合并、箭头函数和函数调用；复杂计算在页面 JS 中算好再放进 `data`。
- `tabBar.list` 的每个 `pagePath` 在 `pages` 中声明，图标文件真实存在。
- `usingComponents`、`include`、`import`、WXS `src`、WXSS `@import` 指向已保存的本地文件，大小写一致。
- 本地图片用 `<image>` 引用，不写进 WXSS 的 `background-image`。

## 4. 云客户端与登录

云客户端只有一种形态：`@tencent-ai/workbuddy-cloud-sdk` 的 `/miniprogram` 子路径，工厂函数为 `createMiniProgramWorkBuddyCloud`。小程序没有 CDN 形态，安装失败时修复网络或源，请求统一走 SDK。

```js
const { createMiniProgramWorkBuddyCloud } = require('@tencent-ai/workbuddy-cloud-sdk/miniprogram')
const { createDiagnosticWx } = require('./workbuddy-cloud-diagnostics')

const cloud = createMiniProgramWorkBuddyCloud({
  endpoint: publicConfig.endpoint,
  publishableKey: publicConfig.publishableKey,
  workBuddyOAuthClientId: publicConfig.workBuddyOAuthClientId,
  wx: createDiagnosticWx(wx),
})

module.exports = { cloud }
```

- `endpoint` 与 `publishableKey` 必填，两者都取自激活返回的客户端配置。`endpoint` 不硬编码，不从环境变量、`location` 或后端转发推导。
- `workBuddyOAuthClientId` 用于 WorkBuddy 账号登录，原样传入，不自行拼接。
- 客户端只初始化一次，各模块复用同一实例。请求与存储的 polyfill 由工厂内部按固定顺序装配。
- 不直接用 `wx.request` 访问数据接口。

登录流程：邮箱验证码、手机短信验证码、邮箱或手机加密码、`wx.login` 换取会话、WorkBuddy 账号授权。微信登录取 `wx.login` 的 `code` 与当前运行环境 appid，交由云端换取会话；客户端不持有 AppSecret，不自建 `jscode2session`，不把 `openid` 当凭据。

登录只建立身份。用户昵称、头像需要用户在小程序内另行填写。

## 5. 环境与数据边界

一个应用对应一个环境，环境属于应用。小程序应用与 Web 应用是两个应用，各有独立的用户体系和数据，互不可见。多端读取同一份记录需要在同一个应用内实现，当前由小程序单端承载云端数据。

云端结构：

| 数据 | 访问方式 |
| --- | --- |
| 训练记录、设置、计划 | 本人读写，`owner_id` 由 `DEFAULT auth.uid()` 填充，RLS 限定到本人 |
| 排名汇总 | 用户主动参与后公开读取，字段限于昵称与分数，客户端不可写 |
| 挑战房间与结果 | 参与者读取，状态由服务端函数改写 |
| 文件 | 本人上传与读取，访问走签名地址 |

数据库只暴露 `public` schema，`auth.uid()` 返回文本。客户端不传 `owner_id`，不传 token，归属由列默认值与 RLS 决定。写入被拒时先看是否 `42501`，缺 grant 或缺策略时补权限，不放宽策略绕过报错。

需要服务端裁决的写入（榜单单分数、挑战结算）用 `SECURITY DEFINER` 函数实现，这类函数绕过 RLS，创建前说明影响范围。删除、清空、批量改动前说明不可逆的范围。

## 6. 工程结构

```text
apps/miniprogram/
  project.config.json                     miniprogramRoot 指向含 app.json 的源码根
  app.json / app.js / app.wxss
  pages/<name>/                           页面，每页 .wxml / .js / .wxss
  components/login-panel/                 登录组件
  utils/cloud.js                          唯一云客户端实例
  utils/workbuddy-cloud-diagnostics.js    失败请求诊断适配器
  utils/workbuddy-data-access.js          单表增删改查封装
  lib/core.js                             共享训练逻辑的编译产物
  .<applicationId>.privacy.json           隐私清单，位于工程根
```

隐私清单逐项枚举代码实际使用的隐私能力，与代码同步更新，缺失会导致发布校验不通过。

`apps/miniprogram` 位于 pnpm 工作区内，构建时确认两件事：工作区依赖能被小程序构建链解析，`miniprogram_npm` 生成到预期位置。依赖安装生成的 `miniprogram_npm` 由发布流程处理，不手工复制。

## 7. 数据模型与同步约定

### 7.1 使用方式

产品保留两种状态：不登录的本地训练，以及用户主动开启的云同步。云同步解决换机后数据延续，数据以本人为边界。

### 7.2 以单次训练为同步单元

- 每条记录分配稳定 `sessionId`，重试上传保持同一 ID。
- 记录保存完成时间、日期、时区约定和结构版本。
- 本地写入与待上传标记一起持久化，区分上传成功、待重试和冲突。
- 统计从有效记录重新计算，不保存累计值。
- 删除写入删除标记，另一台设备据此清理，不回传已删记录。
- 旧数据首次导入前保留本地备份，并写入可重复执行的迁移标记。

合并规则以记录 ID 为准。不使用"同一账号同一天整份覆盖"，也不只用时间戳去重。

### 7.3 页面与数据的关系

云端读写全部异步。页面呈现三种状态：加载中、未登录、已登录；失败时展示 `error.message` 对应的提示，不静默失败。登录或退出后重置会话缓存，退出时清空本页数据。

## 8. 安全边界

源码公开后，任何人都能读取请求逻辑并直接调用接口，后端在客户端完全不可信的前提下工作。

| 内容 | 处理 |
| --- | --- |
| 页面、表结构、RLS 策略、函数定义 | 进入仓库，使用占位配置与虚构数据 |
| `endpoint`、`publishableKey` | 随前端分发，`endpoint` 只取自激活返回的配置 |
| 管理员凭据、微信 AppSecret、会话凭据 | 不出现在仓库、构建产物、日志与截图 |
| 用户记录、身份关联、生产数据导出 | 不进入仓库，调试使用虚构数据 |

`publishableKey` 只标识应用，权限由会话与 RLS 判定，它不进入日志。

必须成立的隔离：未登录请求读不到私有记录；登录 A 读不到、改不到、删不到 B 的记录；改写记录 ID、批量查询条件、请求体中的归属字段都不能越权。验证分别从数据库直连与业务接口两条路径做，不依赖页面是否显示入口。

公开接口按账号与接口限频，限制分页大小与上传体积。用户令牌、手机号、邮箱、私有文件地址不打印。

## 9. 功能实施

### 9.1 核心训练

本地路径先做通：开始、暂停、完成、提前结束，完成后写入一条记录，历史列表与热力图可读。切后台、锁屏、来电、返回前台的暂停与恢复按真机行为处理。动画、震动、声音、分享入口按小程序能力适配。

完成、提前结束、重复点击分别对应一条记录，不产生重复写入。

### 9.2 云同步

登录后写入并回读；开启同步时上传本地待同步记录，拉取云端增量；关闭同步停止上传，已有云端数据保留，用户可导出或删除。

旧 `tgm:*` 数据在用户确认后导入，保留本地备份与迁移标记，重复执行不重复导入。

### 9.3 排行榜与挑战

周榜自愿参加，按有效打卡天数计分，单日设上限，同分按稳定规则排序。汇总单独建表与索引，分页在查询完成。

邀请制挑战按固定周期结算：邀请、加入、退出、到期、结算各一步，状态由服务端函数推进。分数与胜负由服务端计算，客户端只提交原始记录。榜单文案写明为打卡挑战，普通训练历史不直接计入榜单。
